# Решение собственника — язык документов и терминологическая стабильность

Статус: `Approved`
Дата: `2026-08-21`
Владелец решения: собственник ООО «Арвектум»
Репозиторий: `arvectum/arvectum-company`
Связанный стандарт: `docs/governance/TERMINOLOGY-GLOSSARY.md`

## 1. Решение

Собственник установил следующий постоянный принцип для Arvectum Company:

> Всё, что предназначено для чтения собственником и иными русскоязычными участниками управления, должно быть написано на полноценном русском языке.

Допускается использовать английский язык без обязательного перевода в:

- коде;
- идентификаторах и машинных ключах;
- именах файлов, API, протоколов и библиотек;
- `AGENTS.md` и аналогичных внутренних инструкциях для ИИ/программных исполнителей;
- иных документах, явно предназначенных прежде всего для машинного исполнения или межагентного обмена.

Даже в таких документах системообразующие понятия должны сохранять каноническое значение, установленное глоссарием.

## 2. Требование к русскоязычным документам

В документах, предназначенных для человека:

- основной текст должен быть русским, а не смесью русского и английского;
- английский канонический термин допускается при первом употреблении в скобках или в обратных кавычках, если он нужен для точной машинной связи;
- после первого определения должен использоваться утверждённый русский эквивалент;
- технические идентификаторы (`AC-208`, `POS-004`, `AM-2`, `ROD-03`, `CM-3` и подобные) не переводятся;
- при наличии устойчивого русского эквивалента не следует использовать английское слово только по привычке.

## 3. Защита от смыслового дрейфа при переводе

Для системообразующих терминов запрещено полагаться на свободный многократный перевод вида:

`EN → RU → EN → RU → EN`.

Вместо этого действует схема:

```text
канонический идентификатор термина
+ канонический английский термин
+ утверждённый русский эквивалент
+ нормативное определение
```

При обратном переводе русский термин должен сопоставляться напрямую с каноническим английским термином через глоссарий, а не переводиться заново по смыслу.

## 4. Приоритет при расхождении формулировок

Если разные документы используют близкие слова с потенциально разным значением:

1. сначала определяется идентификатор понятия и его запись в `docs/governance/TERMINOLOGY-GLOSSARY.md`;
2. затем применяется нормативное определение понятия;
3. только после этого выбирается удобная русская или английская формулировка для конкретного текста.

Перевод не может расширять или сужать полномочия, область действия, критерии существенности, права доступа, границы данных или условия безопасной остановки.

## 5. Изменение терминологии

Изменение канонического значения системообразующего термина требует версионированного изменения глоссария и проверки влияния на связанные документы.

Редакционная замена русского слова без изменения смысла допустима только тогда, когда связь с каноническим термином и его определением остаётся однозначной.
